# 访问子系统 · 行为契约

给维护者。命令和别名不在这里复制，以 `axs help` 为准，文案生成自 `lib/axs/cli.py`。默认值、路径和 `run/` 文件名只在 `lib/axs/config.py`。退出码常量只在 `lib/axs/codes.py`，由 cli 导出。文件怎么摆、分层图和斜边台账见 [architecture.md](architecture.md#依赖)。

## 模型与术语

本章是名词的唯一说明。后面只使用这些词，不再定义。

### 术语表

实体。

| 术语 | 是什么 |
| --- | --- |
| 节点 node | 叶子端点。不展开，也不叫代理。 |
| 内置策略 | `DIRECT`、`REJECT`。算在全集里，不算节点，但占 `N#`；『不是节点』只约束称呼。 |
| 内置组 | `GLOBAL`。是策略组，不是内置策略。 |
| 策略组 group | 有类型和成员名单。可以没有当前选择。 |
| 选择组 | 类型 `Selector`。手动切换写入的当前选择会保持。 |
| 自动组 | `URLTest`、`Fallback`、`LoadBalance` 的统称，不是字段值。 |
| 中继组 | 类型 `Relay`。 |
| 成员 member | 成员名单里的一条，指向节点、内置策略或策略组。悬空名不是成员。 |
| 订阅 | 远端材料。 |
| 规则 rule | 一条匹配：类型、匹配对象、规则目标。 |
| 规则集 | 被规则点名的一组规则，不是全部规则。 |
| 规则提供者 | 提供规则集的对象。不是来源值 `provider`。 |
| 池 | `load_proxies` 返回的 `proxies` 字典，名字到对象，分类前的全集。不另造 pool。 |

关系。

| 术语 | 是什么 |
| --- | --- |
| 引用 | 策略组指向一个成员的关系，不是动作。 |
| 共享引用 | 同一成员被多个策略组引用。不是环。 |
| 嵌套 | 成员本身是策略组。 |
| 环 | 策略组之间的引用成回路。节点不成环。 |
| 下一跳 | 当前选择这个名字解析到的成员。解析不到就没有下一跳。 |
| 当前选择 now | 状态字段，至多一个。`LoadBalance` 可以没有。 |

运行。

| 术语 | 是什么 |
| --- | --- |
| 规则目标 policy | 一条规则指向的名字。可以是策略组、内置策略或节点。 |
| 规则目标组 | 规则目标里的那个策略组。内置策略和节点不是规则目标组。 |
| 命中 | 按顺序第一条匹配上的规则。 |
| 出口 | 出口链的最后一环，可以是节点、内置策略或自动组。 |
| 出口节点 | 只有出口是自动组时才有，指内核此刻选中的叶子。`LoadBalance` 可以没有，显示 `-`。出口已是节点或内置策略时，不另叫出口节点。 |
| 出口链 | 从规则目标组走到出口。 |
| 切换 | 改某个策略组当前选择的动作。不写配置。 |
| 公网地址 | `net ip` 查到的地址。不是出口。 |

字段：`now` 是当前选择，`all` 是成员名单，`policy` 是规则目标，`proxies` 是上面的全集。`node`、`group`、`member` 只是称呼，不是字段名。类型值和来源值保持英文。不用：机场、线路、智能组、入口组、入口策略、pool。

### 规则与匹配顺序

#### 语法与类型

本地添加只写 `DOMAIN` 或 `DOMAIN-SUFFIX`（`rule_line`：以 `.` 开头的是后缀）。内置网段是 `IP-CIDR` 和 `IP-CIDR6`（`CIDRS`）。控制器类型由 `rule_word` 转成这些词。这是 `rule_word` 的转换词表，列出的是可转换的范围；不保证本订阅会出现这些类型，也不保证内核都用到。词表：`DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`DOMAIN-REGEX`、`DOMAIN-WILDCARD`、`GEOSITE`、`GEOIP`、`SRC-GEOIP`、`IP-ASN`、`SRC-IP-ASN`、`IP-CIDR`、`SRC-IP-CIDR`、`IP-SUFFIX`、`SRC-IP-SUFFIX`、`SRC-PORT`、`DST-PORT`、`IN-PORT`、`DSCP`、`IN-USER`、`IN-NAME`、`IN-TYPE`、`PROCESS-NAME`、`PROCESS-PATH`、`PROCESS-NAME-REGEX`、`PROCESS-PATH-REGEX`、`PROCESS-NAME-WILDCARD`、`PROCESS-PATH-WILDCARD`、`RULE-SET`、`NETWORK`、`UID`、`SUB-RULE`、`MATCH`、`AND`、`OR`、`NOT`。不在其中的按原样大写。`MATCH` 可以没有匹配对象。比较时 `IP-CIDR6` 与控制器的 `IPCIDR` 都收成 `IP-CIDR`（`_rule_key`）。

#### 匹配顺序

`build_file` 的顺序是 `CIDRS`、覆盖文件里的 `PREPEND`、`rules.list`、订阅正文的 `rules`。`dedupe` 保留先出现的一条。覆盖文件把模式设为 `rule`。按这个顺序从上到下，首个命中生效，命中即停。

#### 规则目标

规则目标是策略组、内置策略或节点。是策略组时，它就是规则目标组。本地 `direct` 写成 `DIRECT`。`via` 只接受策略组，服务在跑且 `group_names` 没有它则退出 3（`组名不存在`），未跑不查。`node` 接受节点或内置策略 `DIRECT`/`REJECT`（别名 `d`/`v`/`n`）。服务在跑时，策略组退出 3（`不是节点`），不在全集里退出 3（`节点不存在`）；未跑不查。节点名含空白或逗号则退出 1（「节点名不能含空白或逗号」）。`via` 的组名含空白仍是用法错误，也是退出 1。`node` 绕过策略组，所以没有 Fallback；节点改名后这条规则的目标变成悬空名。`group switch` 只改当前选择，不改规则行。

#### 来源与合并

来源 `prepend` 是 `CIDRS` 加上 `PREPEND`。`CIDRS` 排在前面，是这段的子集。`local` 是 `rules.list`。两处都对不上的记为 `provider`。这个 `provider` 不是规则提供者。

#### 运行时读取

`rule show` 读已安装 `config.yaml` 的 `rules` 原文，服务在不在跑都一样。没有这份配置就是未运行。不读控制器。四列是右对齐的顺序 `#`、`RID`、来源、原文。`#` 从 1 计，只表示当前位置。`RID` 是 `R` 加 sha256 的前 6 位小写十六进制：本地规则哈希匹配对象，同一域名改目标不变；`prepend` 和 `provider` 哈希整条原文。`RID` 不是持久句柄，只能用来删当前这条本地规则。`--local` 只列 `rules.list` 里的规则原文，`#` 从 1，来源固定 `local`，`RID` 仍按域名。

`rule show status` 只打规则路径。每个规则目标组一行，带 `G#`、类型、条数和类型分布，再沿当前选择走到叶子。`LoadBalance` 没有当前叶子时收在 `-`。不列成员，不带延迟。服务未跑时不编下一跳，写「当前选择：-」。没有配置同样是未运行。

#### 与切换的关系

规则决定规则目标。目标是策略组时，切换只改该组的当前选择，不改规则行。`node` 直接指向节点，绕过组，切换不影响它。目标是内置策略时，切换不影响命中，也不改变出口。

#### 规则集

`RULE-SET` 点名一个规则集。规则集由订阅里的规则提供者给出。`merge_dict` 不改规则提供者，刷新后条数随订阅变，这里不写死。本程序不解释 `behavior` 和格式；订阅里的 `domain`、`ipcidr`、`mrs` 原样留给内核。

#### 增删

`add` 和 `del` 只改 `rules.list`（`rules_add`、`rules_del`），仍走快照、锁和重载。合并后位于来源 `prepend` 之后、订阅规则之前。不改订阅，也不改规则集。同一匹配对象再添加，替换本地旧行。服务未跑时，`add` 说明「已写入，启动时生效」，`del` 说明「已删除，启动时生效」。`del` 只收一个参数：`R` 加 6 位小写十六进制按 `RID` 删；含逗号则按 `rule show` 的原文精确匹配；其它按域名删。三条路径对不上都退出 3（`规则不存在`），不改文件。`RID` 或原文命中 `prepend`/`provider` 时退出 3（`不是本地规则`），也不改文件。lab 的 `check` 用真内核核对节点目标：`rule add node` 指向假订阅里的叶子，reload 后 `rule show` 该行来源是 `local`、规则目标是该节点，再 `rule del` 清掉。

`CIDRS` 的地址规则带 `no-resolve`：不为命中它去解析域名。`rule_parts` 只留类型、匹配对象和规则目标，这个附加字段不参与来源比较。

| 规则 | 规则目标 | 切换 |
| --- | --- | --- |
| `DOMAIN-SUFFIX,example.com,某策略组` | 规则目标组 | 影响该组的当前选择 |
| `DOMAIN,leaf.example,某节点` | 节点 | 不影响；改名后悬空 |
| `IP-CIDR,*,DIRECT,no-resolve` | 内置策略 | 不影响 |
| `RULE-SET,某规则集,某策略组` | 规则目标组 | 影响该组的当前选择 |
| `MATCH,某策略组` | 规则目标组 | 影响该组的当前选择 |

### 选择与出口

选择组的下一跳可以是任意成员。自动组接受手动切换。`URLTest` 和 `Fallback` 的当前选择可能被下一轮自动选择覆盖。`LoadBalance` 没有 `now`，切换不产生出口效果。

策略组可以嵌套。引用成环就停，不再往下走。每个策略组至多一个当前选择。共享引用可以让同一个成员有多条到达路径，这不构成第二个当前选择。

出口可以停在自动组。出口节点只在这时存在；`LoadBalance` 可能没有，显示 `-`。

### 视图与编号

组表是 `groups`。默认 `node show` 是规则路径加末端自动组。全量叶子表是 `--all`。成员表是 `members`。完整树是 `--full`（容器去重，成员不去重），可选树是 `--select`，平表是 `--flat`，层次是 `--depth`。

`G#` 按策略组名排序，`N#` 按节点名排序。规则表的 `#` 按当前列表位置从 1 计，右对齐；排序、刷新或插入都会改号，它不是稳定 ID。`RID` 见[规则与匹配顺序](#规则与匹配顺序)，也不是持久句柄。组表用 `G#`，全量叶子表用 `N#`，成员表和树沿用 `G#`/`N#`，`--flat` 不加编号。两套名字编号全局共用，互不占用。悬空名没有编号；内置策略有 `N#`（`N#` 覆盖全部叶子端点）。

### 运维

这些词不进上面的表。

拉取是取订阅正文。合并是把前置、本地和订阅合成一份配置。安装是把这份配置写进运行目录。重载是让正在跑的内核读新配置。刷新是持锁后的拉取、校验、合并和安装；服务在跑才重载。

快照是安装前留下的改前副本。回滚是失败时回到那份副本。锁是刷新锁，被占则不再开始一次刷新。清理是按名单删除运行目录里的文件。健康检查只看服务、端口、控制器和订阅是否过期。对齐是保证服务在跑：已在跑则不动。

持久看开关文件在不在。生效看当前会话有没有注入。四态是 `active`、`pending`、`no-x-session`、`-`。开关关着时效应是 `-`。

内置网段是 `config.CIDRS`，具体写法不进文档。规则来源只有 `prepend`、`local`、`provider`。


## 解析

精确别名优先于全名，其次才是唯一前缀。多个前缀候选时退出 `USAGE`，只打印 `候选：` 加名字，没有第二句。未知词打印用法并退出 `USAGE`。`health` 为隐藏入口（`health`/`k`），不在帮助与用法列出。

## 退出码

| 名字 | 值 | 何时 |
| --- | --- | --- |
| `USAGE` | 1 | 用法不对；代理 status 不是开态 |
| `DOWN` | 2 | 未运行、端口不通或端口被占 |
| `FAIL` | 3 | 控制器、校验、拉取、重载、删除或其它业务失败 |
| `LOCK` | 4 | 刷新锁被占用 |
| `EXPIRED` | 5 | 订阅已过期 |

调用点用这些名字，不写裸数字。成功是 0。`status` 何时非 0 见下文。

## 颜色

`AXS_COLOR=always` 着色，`never` 不着色。否则环境里有 `NO_COLOR` 就不着色。再否则看 `AXS_TTY_OUT` / `AXS_TTY_ERR`，值为 `1` 才着色。这两个变量都没设时，看对应流是不是终端。用法走标准错误，颜色跟这条流。非终端和 `never` 是同一布局，没有 ANSI。

| 用途 | 色 |
| --- | --- |
| 节标题，以及用法里的命令 | 粗体 |
| 帮助里的命令名 | 青 |
| `on` / `enabled` / `active`，运行中、监听、可达 | 绿 |
| 未运行、不通，以及 system 的 `off` | 红 |
| 标签，以及 `off` / `disabled` / `pending` / `-` / `no-x-session` | 灰 |

延迟不足 100 用绿，和可达同一档。100 到 200 黄，超过 200 红。非数字和 `-` 用灰。成员表里的当前 `[*]` 用绿。不着色时文字不变。

## 状态

`axs status` 固定五节。节标题粗体，标签灰，正文缩进两格。顺序是服务、节点、订阅、测试、代理。

```
服务
  状态    运行中（systemd 或手动，pid、时长）或 未运行（systemd 或手动）
  端口    入站 监听或不通 · 控制器 可达或不通
  自启    enabled 或 disabled（刷新：下次 HH:MM（N 后））；没有 systemd 为 -
节点
  路径    每个规则目标一行当前链；读不到为 -
订阅
  剩余    流量和到期；没有记录为未知
测试
  net     上次连通缓存距今多久；没有为 -
  node    上次延迟缓存距今多久；没有为 -
代理
  user    on 或 off
  system  on 或 off（persist enabled 或 disabled）
  session persist enabled 或 disabled · effect active、pending、-、no-x-session
```

刷新时间来自 `systemctl list-timers --output=json` 的 `next` 与 `left`。缺一个就是 `-`。

退出：进程不在或入站不通为 `DOWN`；控制器不通为 `FAIL`；订阅过期为 `EXPIRED`；否则 0。快到期仍是 0。警告只属于这一节。

代理节里，persist 为 disabled 时 effect 固定是 `-`，不写 `no-x-session`。`pending` 只在开关开着、当前会话还没注入时出现。没有 dwm 且开关开着才是 `no-x-session`。`on` / `enabled` / `active` 为绿，其余为灰。

## 服务

随登录会话。有用户级 systemd 就走单元，否则手动拉起内核。

- `start`：已经是本服务则成功。没有配置时 `FAIL`（`没有配置`），不代为刷新。端口被占时 `DOWN`（`端口已被占用`），不点名占用者。
- `stop`：未运行也成功。
- `restart`：先停再起。单元重启失败沿用 `启动失败`。
- `ensure`：不接受参数。已在跑则不动、不刷新。未跑且端口被占则 `DOWN`，不刷新。没有配置也没有订阅地址则 `FAIL`（`没有订阅`）。没有配置但有地址则先刷新再启动。刷新遇到锁则透传 `LOCK`。
- `service enable` / `disable`：同时动服务和刷新定时器。没有 systemd 时 `FAIL`（`没有 systemd`）。

## 订阅

只有一条。地址在运行目录，命令不打印。

- `show` 只显示流量和到期。
- `refresh` 持锁，然后拉取、校验、合并、安装。服务在跑才重载。拉取或校验失败不改已安装配置。重载失败回到改前。没有地址是 `FAIL`（`没有订阅`）。锁被占是 `LOCK`。
- `sub clean` 只删订阅缓存。确认规则和下面的清理相同。

合并时覆盖文件压过订阅正文：规则模式、不允许局域网、TUN 关闭、控制器只在回环。前置规则只出现一次。密钥来自运行目录的文件，不来自订阅正文。

到期：没有记录为未知；已经过期；剩余不足三天为将到期；否则正常。将到期不是失败。测速缓存可以记下节点名和延迟，不记组名、地址、密钥。

## 规则

只做域名或后缀。`direct` 写成 `DIRECT`，`via` 指向策略组，`node` 指向节点或 `DIRECT`/`REJECT`。路径、查询、关键字不做。

服务未运行时只改规则列表，退出 0。`add` 说明「已写入，启动时生效」，`del` 说明「已删除，启动时生效」。服务在跑时，`via` 先查组：不存在则 `FAIL`（`组名不存在`），不写列表、不重载。`node` 先查叶子：是策略组则 `FAIL`（`不是节点`），不存在则 `FAIL`（`节点不存在`）。通过后才持锁、合并、重载。失败则配置和列表一起回到改前。控制器读失败是 `FAIL`（`控制器失败`）。

`show` 读已安装配置里的 `rules` 原文。四列是右对齐的 `#`、`RID`、来源、原文，原文照写，保留 `no-resolve`、逗号和逻辑规则，不重建。来源列是 `prepend`、`local`、`provider`，含义见[模型与术语](#模型与术语)。`RID` 见[规则与匹配顺序](#规则与匹配顺序)。内置网段不是覆盖项，但只占 `prepend`。比较来源只看类型、目标和策略，忽略 `no-resolve`。配置没有则 `DOWN`（`服务：未运行`），服务是否在跑不影响展示。`--local` 把本地规则文件的非空、非注释行写成同样四列，编号从 1，来源固定 `local`。`add` / `del` 只改本地文件。`del` 的参数是域名、`RID` 或规则全文。非本地命中是 `FAIL`（`不是本地规则`）。三条路径没有命中都是 `FAIL`（`规则不存在`），不改文件。

## 组与节点

名词见[模型与术语](#模型与术语)。`--full` 的根是没被其它策略组引用的策略组；全部被引用时用主代理，否则 `GLOBAL`，否则每个策略组。

写出的名字先按精确名称，名称本身是数字也算名称；没有同名对象才按编号。

| 动作 | 缺参 | 多参或未知 | 其它 |
| --- | --- | --- | --- |
| groups | — | `USAGE` | 未运行 `DOWN`，控制器 `FAIL` |
| list | — | `USAGE` | 同上 |
| members | `USAGE`，先看 groups | `USAGE` | 不是策略组或组不存在为 `FAIL`；未运行 `DOWN` |
| switch | `USAGE`，提示用 members 看成员 | `USAGE` | 组不存在、不是策略组或节点不存在为 `FAIL`；未运行 `DOWN` |
| test | 按既定组 | `USAGE` | 没有可测组为 `FAIL`；未运行 `DOWN` |

## 节点

- `groups`：不接受参数，多一个是 `USAGE`。按组名排序，编号是 `G#`，右对齐。一行是 `G#`、组名、类型、当前选择，按显示宽度对齐，不用制表符。有选择时写 `→` 和名字，没有写 `-`。未运行 `DOWN`，控制器失败 `FAIL`。只读。
- `members`：一个组号或组名。缺参是 `USAGE`（提示先看 groups），多参或以 `-` 开头也是 `USAGE`。未运行 `DOWN`。组的解析与 switch 的组参数相同。空成员写 `（无成员）`。一行是 `N#` 或 `G#`、名称、类型、当前则 `[*]`、缓存延迟，按显示宽度对齐，不用制表符。编号与 list、groups 相同。当前 `[*]` 为绿。延迟与 list 同一档。悬空名没有编号，标 `-`。
- `list`：未运行 `DOWN`，控制器失败 `FAIL`，多一个不认识的参数是 `USAGE`。不调用延迟接口，不把节点名写进日志。默认先打粗体「当前规则路径：」（与 `rule show status` 同一段；`axs status` 的节点节不加这行标题），再打「末端组（链尾自动组）：」。各视图末尾有一行暗色说明，`rule show status` 与 `--flat` 除外。链尾行是：`G# 名称 [类型] → N# 当前 · N 个成员`，`LoadBalance` 的当前是 `-`，成员多列、缓存延迟、当前 `[*]`。没有末端组就只有路径。末端组成员不去重，不写「→ 见」。没有已安装配置是 `DOWN`。`--all` 才是全量叶子表，标题是「全部叶子端点（最近测速：…）：」，没有记录时测速为 `-`。叶子含节点与内置策略，不含策略组。按终端宽度排多列。宽度取 `COLUMNS`，否则 `tput cols`，否则 80。选中格以 `[*] ` 开头，编号是 `N#`，只标主代理链上的叶子。`--full` 打树，不带延迟。根是没被别的组引用的组；全部被引用时用主代理，否则 GLOBAL，否则每个组。组内按成员名单向下。容器去重，成员不去重：每个组只在最小深度处展开，同深度按根顺序、再按成员名单顺序取首次；其余出现写 `→ 见 G# 名称（上方/下方）`，已展开写上方，尚未展开写下方。`--depth` 截断不改变展开点，后续仍按最小深度判断。叶子重复，不写「→ 见」。组行 `G#`，叶子行 `N#`，编号与 groups、默认 list 相同。选中的组后加 ` *`，选中的叶子后加 ` [*]`。回到上层栈的组写 `↩`，不继续展开。叶子按显示宽度多列，树线只在第一列。`--select` 分两段，每个 Selector 一块，只列直接成员。上段「当前规则目标组（可切换）：」是规则实际指向的策略组，按出现顺序去重；`DIRECT` 和其他不是组的目标忽略，不从 `GLOBAL` 起。Selector 各成一块。不是 Selector 的规则目标只占一行，不展开；自动组行尾写「自动·手动切换会被覆盖」，因此 LoadBalance 不列出出口节点。下段「成员引用（仅被其他组引用的组）：」从这些 Selector 的成员做广度遍历，收集其余 Selector，按组号排序；只经过自动组才能到达的不收。没有则整段省略。组头缩进两格，成员用 `├─`/`└─`，板块之间空一行。叶子写 `N# 名称`，按终端宽度多列，首行带树线，续行对齐；组类仍一行一个。当前选择一律 ` [*]`。嵌套 Selector 写 `G# 名称 [Selector]`，再加 `→ 见当前规则目标组` 或 `→ 见成员引用`，不在块内展开。其它直接成员写 `G# 名称 [类型]`，不展开。悬空名不显示。环只留这行引用，不写 `↩`。编号与 `--full` 相同。`--depth N` 从 1 计，两段一样：1 只打各块组行，2 及以上再打直接成员，不再往下。`--flat` 或 `-l` 仍是制表符表：星号或空、名称、类型、组名。
- `test`：多一个参数是 `USAGE`。控制器延迟，不是端到端。不写组名时按既定顺序挑一个可测组；没有则 `FAIL`（`没有可测组`）。写出的组名或组号先按精确名称，没有这个名字才按编号；名字若不是组则 `不是策略组`，编号对不上则 `组不存在`。每次真正测完都写缓存。成功时再记节点名到延迟，并丢掉与所测组同名的键。
- `switch`：要组、再要成员。缺一个是 `USAGE`（提示用 members 看成员），多一个也是 `USAGE`。未运行 `DOWN`。第一个参数与 `test` 同样解析组。组不在为 `组不存在`，在但不是策略组为 `不是策略组`，节点不在该组为 `节点不存在`。三者都是 `FAIL`，而且不发选择。类型不是 Selector 也不拒绝。URLTest/Fallback 的选择可能被下一轮自动选择覆盖；LoadBalance 无 now，设置不产生出口效果。第二个参数先匹配组内同名成员，数字名字也算名字；否则才按当前全局编号解析。成功退出 0，打印组名、节点、缓存延迟（没有则 `-`）。不改配置，不持刷新锁。

## 网络

`net test` 的目标依次是参数、运行目录里的网址表、内置表。非法网址是 `USAGE`（`用法错误`）。`AXS_FORBID_NET=1` 时目标必须在回环名单内，否则整次 `FAIL`（`禁止外网`），一行不测。入站不通是 `DOWN`（`入站：不通`）。进入实测后写连通缓存：全通为 `ok` 并退出 0，有不通为 `fail` 并退出 `FAIL`。预检失败不写缓存。

`net ip` 不接受参数。经入站查询出口地址。入站不通 `DOWN`，查询失败 `FAIL`（`出口查询失败`）。禁止外网时同样 `FAIL`。

## 清理

先停服务，否则 `DOWN`（`服务在运行，先 axs stop`）。名单里的名字不得含斜杠或 `..`。符号链接若指向运行目录以外，整次 `FAIL`（`路径越界`），一个都不删。没有 `--yes` 时，先把将删的已存在路径打到标准输出；不是终端就 `USAGE`（`需要 --yes`）；是终端再问，只有 `y` 或 `yes`（大小写不限）才删。不存在的项跳过，所以删空也是 0。删除本身失败是 `FAIL`（`删除失败`）。

## 代理

服务只听回环上的混合端口。三层只决定谁去连它，不改内核进程。默认不注入。`proxy user` 与现有 `setproxy` 一样，都是显式打开。

存在性开关只看文件在不在，名字以 `.flag` 结尾：`run/proxy-session.flag`、`run/proxy-system.flag`。`enable` 写成 0600，并删掉改名前的旧文件。

| 动作 | 做什么 |
| --- | --- |
| user on | 标准输出八行 export（http、https、all、no，大小写各一份），给 eval 用。标准错误提示需要 eval。不改当前进程的环境 |
| user off | 标准输出一行 unset |
| user status | 环境指向本代理则 `on` 退出 0，否则 `off` 退出 `USAGE` |
| system on | 只写 gsettings：manual、回环主机、混合端口、忽略名单。不写开关。没有 gsettings 命令则 `FAIL` |
| system off | mode 设为 none。不做 schema 级重置，不删开关 |
| system enable | 写系统开关。重登 X 之后，登录脚本才导出桌面标识 |
| system disable | 删系统开关 |
| system status | 运行时是 manual 且主机、端口指向本代理则 `on` 退出 0，否则 `off` 退出 `USAGE`。下一行是 persist `enabled` 或 `disabled`。会话标识含 GNOME 为 `effective`；没有 X 会话为 `no x session`；否则 `pending` |
| session enable | 写会话开关。没有 on/off |
| session disable | 删会话开关 |
| session status | 开关不在：persist `disabled`，effect `-`，退出 `USAGE`。钩子缺失也退出 `USAGE`。没有 X 会话：effect `no-x-session`。已经注入且指向本代理：effect `active`，退出 0。否则 effect `pending`，退出 `USAGE` |

会话环境读 dwm 进程的 environ。`AXS_SESSION_PID` 可以指定测哪个进程。

登录脚本有两块，插入时都要判重。会话开关在时导出代理变量。系统开关在时导出 `XDG_CURRENT_DESKTOP=GNOME`。都要重登 X 才生效。`no_proxy` 只含 config 里的回环名单，私网例外由内核规则承担。

libproxy 的 gnome 插件和 Edge 都要会话里有这个桌面标识，才读 gsettings。没有标识时走 direct。浏览器用 session 层。副作用是有的应用会把会话当成 GNOME。

## 健康

`health` 为隐藏入口（`health`/`k`），不在帮助与用法列出。`service` 内别名仍是 `he`。通过时无输出，退出 0。失败时标准错误只有一行：`未运行` 或 `端口不通` 为 `DOWN`，`控制器不通` 为 `FAIL`，`订阅过期` 为 `EXPIRED`。不读测试缓存，不拉订阅，不跑延迟。快到期仍是静默 0。

## 透明性

其它工具保持原来的用法，不必知道代理存在。环境变量必须显式打开，盖不住不认变量的程序。不用包装器占命令名。TUN 可以在网卡层转发，但覆盖文件固定关闭，现在不启用。所以当前还做不到对其它工具无感。
