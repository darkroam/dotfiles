# 访问子系统 · 整体规划设计

> 状态：v1 代码已在本目录（2026-10-15）。系统单元仍未安装。
> 依据：R23 要求 §十一、§十二。阶段二实施方案里依赖 Verge、写入 `~/.config/mihomo`、包装 codex 的部分作废。
> 权威：默认值、子命令、退出码只维护在本文。README、roadmap、constraints、轮次档案只引用，不另写一套数。

## 1. 功能清单

v1 只做从无到有的最小闭环。下面每一项都要能单独验证，做完再加下一档。

### v1（必要）

| 能力 | 行为 |
| --- | --- |
| 服务 | `start` / `stop` / `status` / `restart`。用户服务，随登录会话，不设 lingering |
| 订阅 | 用户自己提供一条地址。`get` 只显示流量与剩余有效期；`refresh` 拉取、校验、合并、必要时重载 |
| 节点 | `groups` 只读，组名运行时从控制器发现。`test` 做连通性与延迟。不做 `switch` |
| 规则 | 域名或后缀，持久保存。方向只有 `via`（进指定策略组）和 `direct`。路径、查询、关键字不做 |
| 健康 | 进程、入站端口、控制器三级。`status` 与 `health` 都带订阅剩余有效提示 |

### 明确不在 v1

交互菜单、多条订阅、节点切换、路径级规则、TUN 启用、包装或改名其它命令、开机无人值守、读 Verge 数据目录、把任何文件提交进主仓库。

### 迭代（v1 之后，另授权）

1. 节点 `switch`（只打控制器，不手改展开后的配置）。
2. TUN 透明转发（见 §2）。
3. 多条订阅、本地规则集文件（规则变多、前置列表难维护时再换）。
4. 跨机器再议。v1 只在本机。

## 2. 透明性

原则：其它工具保持原来的用法，不必知道代理存在。

三条路：

| 路径 | 是否改变用法 | v1 |
| --- | --- | --- |
| 环境变量 | 要。SSH 与不认变量的程序盖不住。现有 `setproxy` 属于这种人工桥 | 不接入，也不新增 `proxy` 函数 |
| 包装器 | 要。占命令名会挡住原命令。codex 包装器取消 | 不做 |
| TUN | 不必改命令。流量在网卡层转发 | 候选，不启用 |

v1 的实现路径：只在回环上跑 mihomo（rule），用域名规则决定 via 或 direct。不改其它工具的启动方式，不导出代理变量。因此 v1 **还没有**做到「工具无感」；无感要等 TUN。在那之前，已经在用 `setproxy` 的人照旧自己开，那不是本子系统的接口。

TUN 评估：现二进制带 `with_gvisor`，具备用户态栈条件。启用还要 `CAP_NET_ADMIN` 或 root，会改路由，配错会把本机网络切黑，也越过「先不落地系统服务」的门禁。v1 的覆盖文件固定 `tun.enable: false`，不写栈、不写地址。启用留到系统落地另一次授权。

## 3. 工具选型

- 内核：本机已有的自编译二进制 `~/.local/bin/mihomo`。用户口径是 v1.19.21。阶段一 `mihomo -v` 只打出 Mihomo Meta、go1.27.1，没有打出该版本标签。实现就用这个文件，文档不把未印出的标签写成已证实事实。
- 订阅：用户写入运行目录里的地址文件，由本子系统下载。不读 Verge，不依赖它的数据目录，Verge 可卸。
- v1 只有一条订阅。
- 控制面只走 mihomo 控制器 API。不另存节点凭据，日志和文档不打印地址、密钥、节点名。本机终端里 `groups` / `test` 可以显示组名和延迟，因为操作者需要看。

## 4. 目录与脚本

本地 git 只跟踪代码和文档。密钥与订阅放在 `run/`，该目录不入库。

```
~/.local/lib/access/
  bin/axs                 唯一入口
  lib/merge.py            订阅与覆盖的合并
  lib/common.sh           锁、原子写入、控制器调用
  tests/                  夹具与回归
  docs/                   README、design、constraints、roadmap
  run/                    不入库。0700
```

`run/` 内容：

| 文件 | 权限 | 内容 |
| --- | --- | --- |
| `subscription.url` | 0600 | 地址原文。只有刷新读取 |
| `secret` | 0600 | 首次启动在本地生成。不从 Verge 复制，命令不打印 |
| `override.yaml` | 0600 | 本文默认值的落地件。无节点、无地址 |
| `rules.list` | 0600 | 本机域名规则 |
| `config.yaml` | 0600 | 合并结果。`mihomo -d` 指向 `run/` |
| `config.yaml.bak` | 0600 | 最近一次成功配置 |
| `userinfo` | 0600 | 上次刷新缓存的流量与到期，不含地址 |
| `refresh.lock` | — | 刷新与规则改写共用 |

阶段二把运行目录放在 `~/.config/mihomo`。那个目录主仓库没有忽略。v1 改到已经全局忽略的本树 `run/`，避免订阅被宽 glob 扫进公开仓库。

单元文件本阶段不安装。落地时（另授权）才写用户单元：`axs.service` 执行 `mihomo -d <run>`；`axs-refresh.timer` 每 12 小时跑一次刷新。第一次写出合格 `config.yaml` 之前不 enable。

## 5. 子命令与退出码

命令名 `axs`。避开已有的 `/usr/bin/proxy`，也避开 mihomo / clash 字样。

```
axs start|stop|status|restart
axs sub get|refresh
axs rule list
axs rule add via <域名> <策略组>
axs rule add direct <域名>
axs rule del <域名>
axs node groups
axs node test [策略组]
axs health
```

域名规则：无方案、无路径、无问号。前缀 `.` 表示后缀（`DOMAIN-SUFFIX`），否则是整域（`DOMAIN`）。`via` 的策略组必须由调用者写明，不猜测「主组」。

`rule add via` 在服务运行时先向控制器查询组名。组不存在，或这次查询失败，则退出 3，不写 `rules.list`，也不重载。服务未运行时控制器不可用，仍只把规则记下来，启动时再生效。mihomo 遇到未知组会不会拒绝加载，本设计不预设；等系统落地时实测一次再记。

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 成功。快到期只是提示，仍为 0 |
| 1 | 用法错误 |
| 2 | 服务或端口不可用；`start` 时端口已被占用也是 2 |
| 3 | 拉取、校验、合并、重载失败，或服务在跑但组名不存在。后一种情况不写规则列表 |
| 4 | 锁被占用 |
| 5 | 仅 `health`：进程与端口正常，但订阅已过期 |

`node test` 里单个节点超时是结果数据，不是失败。API 本身失败才是 3。

| 项 | 值 |

| 入站 | 只留 mixed，`7897`，仅回环。与现有 `setproxy` 相同，便于人工桥继续可用 |
| 控制器 | `127.0.0.1:9097` |

| ipv6 | 开 |

| tun | `enable: false` |
| 日志 | info，走 journal。不写订阅与密钥 |
| 刷新 | 12 小时。手动与定时器共用一把锁 |
| 到期提示 | 剩余不足 3 天：`status`/`health` 打印警告，退出码仍 0 |
| 测速目标 | `https://www.gstatic.com/generate_204` |
| 前置直连 | `localhost`、`local`、`goproxy.cn`，以及 gh-proxy 一类后缀。回环与私网网段由脚本在运行时插入，不写进文档 |

订阅里的端口、控制器、单独的 http/socks/redir/tproxy、打开的 tun，合并时被上表压掉。映射项只覆盖写明的键，DNS 上游仍留订阅里的值。

## 7. 订阅与规则怎样生效

刷新每次用**刚下载的订阅**重新合并，不往旧配置上叠。顺序：运行时生成的回环与私网直连、覆盖文件里的前置直连、`rules.list`、订阅原规则。

校验至少要看到代理节点列表。失败则留下旧的 `config.yaml` 与旧订阅正文，退出 3。服务已在跑时，校验通过才调控制器重载；重载失败同样回滚。服务没在跑时，写完配置即停，不重载。

`sub get` 只读 `userinfo`。没有这块缓存就打印「未知」，不当成故障。

## 8. 健康与并发

健康不是「节点都能用」。节点死活看 `node test`。

`health` 顺序：进程在 → mixed 能连 → 控制器 `/version` 通（密钥从文件读）。三步都过才看到期：已过期退出 5；快到期打印警告仍退出 0；没有到期字段打印「未知」仍退出 0。健康检查不拉订阅、不删配置。

| 操作 | 服务未运行 | 服务在运行 |
| --- | --- | --- |
| start | 端口空闲则启动；占用则退出 2，不提示某个具体程序 | 已是本服务则退出 0 |
| stop | 退出 0 | 停止 |
| rule add/del | 只改 `rules.list`，退出 0，并说明启动时生效 | `via` 先查组，通过后才持锁、重复合并、重载。失败则配置和规则列表一起回到改前 |
| refresh | 持锁、拉取、合并、不重载 | 持锁、拉取、合并、重载。失败保留旧配置 |
| 定时器与手动同时 | 后到的退出 4 | 同左 |
| via 的组名不存在 | 规则先记下（此时查不了控制器） | 先查控制器；不存在则退出 3，不写列表、不重载 |

不再探测 Verge。端口冲突一律是「端口已被占用」。

## 9. 测试策略

先有失败测试，再写实现。每个 bug 先加一条能复现它的测试，修完保持为回归。

v1 基线（不连真实订阅、不启真实进程）：

| 夹具 | 断言 |
| --- | --- |
| ShellCheck | `bin/` 与 `lib/` 的 shell 为 0。合并逻辑用 Python 时另跑语法检查 |
| 假订阅合并 | 模式、入站、DNS 监听、tun 关闭、前置规则只出现一次、密钥来自文件而不是订阅正文 |
| 规则增删 | 服务未运行只改列表；服务在跑且组名不存在时退出 3、列表不变、不重载；其它重载失败时列表与配置都回到改前 |
| 并发锁 | 两路刷新，一路成功，另一路退出 4 |
| 健康样本 | 端口不通为 2；端口通但控制器不通为 3；已过期为 5；三天内到期仍为 0 且输出含警告 |

假订阅放在 `tests/fixtures/`，里面没有真实地址。基线能重复跑通之前，跟踪文档若被允许引用，名称写作「访问子系统（孵化中）」。本阶段不改跟踪文档。
