# 文档质量规范

本文档定义 `.local/share/docs/` 下所有文档的文件级质量要求。
项目级约束（工作流、跟踪范围、平台事实规则）见[维护策略](maintenance-policy.md)。

---

## 总体原则

文档与代码同等重要。所有文档必须满足：

- **清晰**：读者能快速理解，无需猜测
- **完整**：覆盖所负责模块的全部必要信息
- **准确**：与实际配置和代码一致，无过时或错误
- **一致**：术语、格式、命名在全项目统一
- **可读**：面向目标读者，行文符合其认知水平
- **可查找**：结构合理，便于快速定位

## 文档架构

### 目录结构

```
docs/
├── README.md                # 文档索引（导航入口）
├── user/                    # 用户指南（最终用户）
├── project/                 # 维护者文档（Agent/开发者）
├── planning/                # 项目跟踪（待办、历史、缺陷）
├── platforms/               # 平台部署（设备/发行版事实）
└── audits/                  # 审计记录（按日期归档）
```

### 命名规则

- 文件名使用 kebab-case（如 `desktop-guide-zh.md`）
- 中文文档以 `-zh` 后缀，英文文档以 `-en` 后缀（当前仅根 README.md 为英文）
- 审计记录按 `YYYY-MM-DD-{scope}.md` 格式

### 文件归属

| 目录 | 职责 | 读者 |
|------|------|------|
| `user/` | 安装、使用、个性化、故障处理 | 最终用户 |
| `project/` | 架构、依赖、策略、设计决策 | Agent/维护者 |
| `planning/` | 活动待办、挂起项、历史、缺陷 | Agent/维护者 |
| `platforms/` | 设备事实、发行版映射、验证状态 | 运维/Agent |
| `audits/` | 审计发现、执行记录、进度表 | Agent/维护者 |

新建文件前，确认其职责不属于已有文件。仅在形成明确配置或维护边界时才新建文件。

## 文件内部结构

### 标题层级

- 每个文件仅有一个 `#` 一级标题
- 使用 `#` `##` `###` 最多三级，避免四级及以上
- 标题应简洁明确，能独立表达章节内容

### 段落与列表

- 段落不超过 5–8 行，避免大段文字堆砌
- 流程、对比、枚举类内容优先使用列表或表格
- 长列表考虑分组或拆分为子章节

### 代码与命令

- 关键操作须配可运行的代码示例
- 代码块标注语言（如 ` ```bash `、` ```conf `）
- 命令示例必须可直接复制执行，不含占位符（除非明确标注）

### 链接与引用

- 内部链接使用相对路径（如 `[维护策略](maintenance-policy.md)`）
- 跨目录链接注明相对位置（如 `[待办](../planning/todo.md)`）
- 避免信息孤岛：相关文档之间应互相引用

### 篇幅指导

- 散文类文档建议不超过 500 行；超过时考虑拆分
- 结构化数据（审计记录、缺陷列表）不受此限制
- 过短的文档（< 20 行）考虑是否应合并到上级文档

## 完整性自检

每个文档应能回答以下问题：

1. **目标读者是谁？** — 一句话说明
2. **读者阅读本文后能做什么/知道什么？** — 明确学习目标
3. **是否包含所有必要信息？** — 步骤、参数、示例无遗漏
4. **是否标注了常见问题或边界情况？** — 减少读者困惑
5. **是否引用了相关文档？** — 建立文档网络
6. **内容是否与当前实际一致？** — 无过时描述

## 行文风格

### 按读者分类

| 读者 | 文档类型 | 行文要求 |
|------|----------|----------|
| 最终用户 | 使用指南、快捷键 | 简洁直白，任务导向（"如何做 X"），避免术语，多配示例 |
| Agent/维护者 | 架构、策略、审计 | 精确严谨，关注模块关系和决策理由，可引用代码路径 |

### 语言

- 除根 `README.md` 使用英文外，所有文档使用中文
- 命令名、路径、代码标识、许可证和必要上游引用保持原样
- 同一概念在全项目使用相同术语（如"跟踪"不混用"追踪"）

### 独立性

- 同一份文档不得同时面向多类读者
- `architecture.md` 与 `desktop-guide-zh.md` 因读者不同存在内容重叠是设计意图，两者各自独立完整

## Agent 文档维护规范

### 何时更新

Agent 必须在以下时机更新文档：

- **配置变更** → 同步更新对应架构/接口文档
- **新增功能** → 同步新增用户指南或说明
- **发现错误** → 立即修正，并检查是否有其他文档存在同类错误
- **文档重构** → 更新索引和关系图

### 输出格式

完成文档任务后，Agent 应输出：

1. **影响分析**：列出本次变更涉及的文档文件
2. **变更摘要**：说明在每个文件中做了什么修改
3. **完整性确认**：逐项检查前述完整性清单
4. **下一步建议**：是否需要人工复核或补充

### 质量红线

以下情况视为文档缺陷，Agent 应主动报告并修复：

- 文档描述的功能在实际配置中不存在
- 命令/参数示例无法执行
- 未标注目标读者或读者定位错误
- 同一术语在不同文档中含义不一致
- 内部链接失效或指向已删除文件
